# 发薪周期预算日历 PWA 设计规格

## 1. 文档信息

- 日期：2026-09-16
- 状态：已确认（2026-09-16 修订发薪周期规则）
- 产品形态：面向 iPhone 的本地优先 PWA
- 目标设备：iPhone 16 Pro Max
- 数据策略：静态网页托管，账目仅保存在设备本地

## 2. 背景与目标

传统记账产品通常按照自然月统计，重点回答“已经花了多少”。本产品以实际工资到账日为周期起点、下次工资到账日前一天为周期终点，重点回答“今天还能花多少”，并通过日结余滚存、周结余均摊和超支后重规划来约束可变消费。周期不会按固定 28 天自动滚动，避免与真实发薪日逐月偏离。

第一版目标：

1. 用尽量少的操作完成手动记账。
2. 始终清晰展示今日、当周和整个周期的剩余预算。
3. 按实际发薪间隔准确执行动态预算算法，不产生金额累计误差。
4. 同时记录可变消费和固定支出，但只有可变消费占用周期预算。
5. 完全离线可用，账目默认不离开 iPhone。
6. 能够导出完整备份，并在新设备或数据丢失后恢复。

## 3. 第一版范围

### 3.1 包含

- 以实际工资到账日创建新周期。
- 设置并可调整下次预计发薪日，周期天数按两个日期的实际间隔计算。
- 每 7 个周期日组成一周，最后一周允许不足 7 天。
- 自定义周期总预算。
- 今日、当周、周期预算展示。
- 日结余转入次日。
- 周结余平均分配到下一周。
- 当日超支后重新分配所有未来日期预算。
- 可变消费与固定支出双轨记录。
- 支持一个快捷项目配置多个预设金额。
- 一键记账、5 秒撤销、通用手动记账。
- 账目查看、补记、修改和删除。
- 7 列、4—5 行为主的可变长度周期日历；更长周期继续增加行数。
- 周期统计、分类统计和历史周期对比。
- IndexedDB 本地持久化。
- PWA 离线运行和添加到主屏幕。
- 完整备份导出与恢复。

### 3.2 不包含

- 用户注册和登录。
- 后端业务服务和远程数据库。
- 多设备自动同步。
- 微信、支付宝、银行卡账单自动导入。
- 银行卡或信用卡账户余额管理。
- 收入管理。
- 多人共享账本。
- App Store 上架、TestFlight 或原生 iOS 客户端。
- Face ID 或应用内密码锁。
- 分类独立预算。
- 推送通知。

## 4. 核心概念

- **发薪周期**：从一次实际工资到账日开始，到下一次实际工资到账日前一天结束的一期预算范围。
- **预计发薪日**：创建当前周期时填写的下一次预计工资到账日期，用于提前计算当前周期预算；可在实际到账前调整。
- **周期预算**：一个发薪周期内允许使用的可变消费总额。
- **预算消费**：餐饮、交通、饮料、购物等占用周期预算的可变支出。
- **固定支出**：房贷、话费等需要记录和统计，但不占用周期预算的支出。
- **基础日预算**：系统为某日分配的预算，不包含前一日滚入的结余。
- **今日可用**：基础日预算加前一日滚入结余，若总预算已耗尽则为 0。
- **日结余**：今日可用减当日预算消费，结果为正时滚入次日。
- **周期周**：从周期开始日起每 7 个自然日为一周；最后一周按周期剩余实际天数组成。
- **周结余**：当周预算减当周预算消费，结果为正时加入下一周，再按下一周的实际天数平均分配。
- **周期盈余/超支**：周期预算减周期预算消费。正数为盈余，负数的绝对值为超支。

## 5. 信息架构与页面

底部主导航为：`首页｜记账｜历史｜设置`。记账使用居中的突出按钮。

### 5.1 首页

采用已确认的“今日 + 周期平衡”方案，按以下顺序展示：

1. 标题“预算日历”和当前周期日期范围。
2. 今日可用、周期剩余、剩余天数。
3. 高频快捷项目及其预设金额。
4. 7 列可变行数的发薪周期日历。
5. 今日账目明细。

日历状态：

- 今日使用主蓝色突出。
- 有预算消费的日期显示消费标记。
- 超出当日可用的日期显示珊瑚红提示。
- 未到日期使用弱化样式。
- 点击日期进入该日详情。

### 5.2 记一笔

- 顶部选择“预算消费”或“固定支出”。
- 显示快捷项目和预设金额。
- 支持输入任意金额。
- 支持选择项目、日期和备注。
- 默认日期为今天。
- 金额必须大于 0，最多保留两位小数。
- 保存后显示 5 秒撤销提示。

### 5.3 日期详情

- 展示日期、当日基础预算、滚入结余、今日可用、预算消费合计和当日结余/超支。
- 分组展示预算消费和固定支出。
- 支持补记、修改和删除。
- 任何历史账目变化都会触发整个周期重新计算。

### 5.4 历史与统计

当前周期展示：

- 周期预算、预算消费、周期盈余/超支。
- 固定支出总额，并明确标注“不占预算”。
- 各周期周支出柱状图。
- 项目或分类占比图。
- 每周预算、实际支出、结余或超支。

历史周期展示：

- 周期日期范围。
- 周期预算、预算消费、盈余/超支。
- 固定支出总额。
- 连续周期预算完成率趋势。

### 5.5 设置

- 展示并允许修改当前周期的预计发薪日。
- 提供“工资已到账，开始新周期”操作，并配置新周期预算和下次预计发薪日。
- 管理快捷项目、多个预设金额、类型、图标、颜色、排序和启用状态。
- 导出备份、恢复数据。
- 显示版本和安装到主屏幕的说明。

## 6. 快捷记账交互

一个项目可以拥有一个或多个金额预设。例如“地铁”有 2.70 元和 3.60 元两个独立按钮。

点击预设金额后：

1. 立即为今天创建账目，不再弹出确认框。
2. 项目的默认类型决定其属于预算消费还是固定支出。
3. 页面底部显示“已记录，撤销”提示，持续 5 秒。
4. 撤销会删除刚创建的账目并重新计算预算。
5. 5 秒后仍可在今日明细或日期详情中修改、删除。

“其他金额”进入通用记账页，不直接保存。

## 7. 周期规则

### 7.1 日期

- 首期开始日由用户选择，语义为本次实际工资到账日。
- 创建周期时必须填写下次预计发薪日，且必须晚于开始日。
- 下次预计发薪日默认取下个月同一日；若下个月没有该日期，则取该月最后一天。默认值始终允许用户修改。
- 活跃周期的预计结束日为下次预计发薪日前一天；该日期用于计算当前预算安排。
- 工资实际到账后，由用户明确点击“工资已到账，开始新周期”。旧周期最终结束日改为实际到账日前一天，新周期开始日为实际到账日。
- 周期天数按开始日到结束日的实际自然日数计算，不写死为 28、30 或 31 天，以兼容二月、周末、节假日和工资延期。
- 日期使用设备本地的 `YYYY-MM-DD` 日期字符串保存，不用 UTC 时间推导自然日，避免跨时区导致日期移动。
- 从周期开始日起，每 7 个连续自然日为一个周期周；最后一周使用剩余实际天数。

### 7.2 周期衔接

- 每期完全独立，上期盈余和超支不带入下一期。
- 应用不得仅因预计发薪日到达而自动创建下一期，也不得自动补建空周期。
- 用户可在工资提前到账时立即开始新周期；系统将旧周期结束日调整为新周期开始日前一天，并重新计算旧周期。
- 到达或超过预计发薪日但尚未确认工资到账时，应用进入“等待发薪确认”状态，暂停显示新的今日可用，并要求用户选择“工资已到账”或“还未到账，调整日期”。
- 用户选择“还未到账”后必须把预计发薪日延后；系统按新的周期结束日对当前周期剩余预算重新计算。
- 若新周期开始日当天已经存在旧周期账目，确认界面明确提示，这些账目将原子地转入新周期，避免同一天跨两个周期。
- 开始新周期时默认沿用上一期预算，但用户必须确认或修改本期预算，并设置新的下次预计发薪日。
- 每期单独统计预算、预算消费、盈余/超支和固定支出。

## 8. 金额精度与分配

### 8.1 基本原则

- 数据库中的金额一律以整数“分”保存。
- 页面仅在展示和输入时转换为“元”。
- 不使用浮点数执行预算计算。
- 平均分配产生的余数按日期从早到晚每次补 1 分，直到余数分完。

例如 375.00 元平均分配到 7 天：第一天 53.58 元，其余 6 天各 53.57 元，总额严格等于 375.00 元。

### 8.2 初始分配

1. 计算周期包含的实际自然日数。
2. 周期总预算直接平均分配到全部周期日。
3. 无法整除的余数分按日期从早到晚每次补 1 分。
4. 每周初始预算等于该周所含日期的基础日预算之和，因此不足 7 天的最后一周按实际天数获得预算。

## 9. 动态预算算法

预算结果不作为权威数据保存，而是由周期配置和账目确定性计算得出。新增、修改、删除或恢复账目后，从周期第一天重新计算。

预算引擎每次计算必须接收设备本地“截至日期”：只有截至日期之前、已经结束的自然日才执行日结余或周结余滚存；截至日期当天只显示当前可用和实时剩余，不提前把当天结余转入明天。当天一旦超支则立即重规划未来日期。归档周期按结束日次日作为截至日期，从而完成最后一天结算。未来日期没有账目不得被视为“已经一天未消费”。

### 9.1 日内消费未超过今日可用

- `日结余 = 今日可用 - 当日预算消费`
- 日结余大于 0 时全部滚入次日。
- 周内次日的基础日预算不变，今日可用增加滚入结余。

### 9.2 周末仍有结余

每个完整 7 天周期周结束时，如果后面仍有周期日：

1. 计算本周总可用预算减本周预算消费。
2. 正结余加入下一周原计划预算。
3. 新的下一周预算按下一周实际包含的天数平均分配；最后一周不足 7 天时只分到这些实际日期。
4. 最后一周结余直接成为周期盈余，不再分配。

周结余只向下一周移动，不直接平均到所有剩余周。

### 9.3 当日超支

当某日预算消费大于该日“今日可用”时触发全局重规划：

1. `剩余金额 = max(周期预算 - 截至当日累计预算消费, 0)`。
2. `剩余天数 = 周期结束日 - 当日`，不包含当日。
3. 将剩余金额平均分配给全部剩余日期，余数分优先分给较早日期。
4. 重规划后原先未使用的未来周预算和结余计划失效，以新分配结果为准。
5. 次日以后再次发生结余或超支时继续应用同一套规则。

### 9.4 周期预算耗尽

- 累计预算消费达到或超过周期预算后，所有未来日期今日可用显示为 0。
- 仍允许继续记录账目。
- 顶部显示“已超支”及超支金额。
- 周期结果记录为超支。

### 9.5 固定支出

- 固定支出不进入任何日、周或周期预算公式。
- 固定支出出现在日期明细和统计中，单独汇总。

## 10. 数据模型

### 10.1 `cycles`

- `id`
- `startDate`
- `endDate`
- `expectedNextPayDate`
- `totalBudgetCents`
- `status`：active、archived
- `createdAt`
- `updatedAt`

活跃周期中，`endDate` 始终等于 `expectedNextPayDate` 的前一天。归档时，`endDate` 固化为下一周期实际开始日的前一天；`expectedNextPayDate` 保留为当时预期值，供历史分析预计与实际发薪日期差异。

### 10.2 `projects`

- `id`
- `name`
- `icon`
- `color`
- `expenseType`：budget、fixed
- `sortOrder`
- `isActive`
- `createdAt`
- `updatedAt`

### 10.3 `projectPresets`

- `id`
- `projectId`
- `amountCents`
- `sortOrder`

### 10.4 `transactions`

- `id`
- `cycleId`
- `projectId`
- `expenseType`：budget、fixed
- `amountCents`
- `localDate`
- `note`
- `createdAt`
- `updatedAt`

账目保存当时的 `expenseType`。之后修改项目默认类型不会追溯改变历史账目。

### 10.5 `settings`

- `key`
- `value`

用于保存默认周期预算、界面偏好、备份提醒状态和数据库版本等设置。

## 11. 应用架构

### 11.1 运行形态

- HTTPS 静态托管应用程序文件。
- 无后端业务服务。
- 无远程数据库。
- PWA Manifest 提供名称、图标、主题色和主屏幕启动方式。
- Service Worker 缓存应用外壳，使应用断网可启动。
- IndexedDB 保存全部业务数据。

### 11.2 模块边界

- **界面层**：页面、组件、交互状态和无障碍适配。
- **预算引擎**：纯函数实现周期分配和重算，不直接访问界面或数据库。
- **账目服务**：账目新增、修改、删除和撤销。
- **数据仓库**：封装 IndexedDB、数据库迁移和事务。
- **统计服务**：按周期、周、项目聚合。
- **备份服务**：导出、校验和恢复。
- **PWA 外壳**：离线缓存、安装信息和版本更新。

## 12. 数据流

### 12.1 一键记账

1. 用户点击预设金额。
2. 账目服务验证项目、金额和日期。
3. 数据仓库在 IndexedDB 中写入账目。
4. 预算引擎从周期第一天重算。
5. 首页和统计更新。
6. 显示 5 秒撤销入口。

### 12.2 修改历史账目

1. 用户提交修改。
2. 数据仓库在事务中更新账目。
3. 预算引擎重算整个所属周期。
4. 若计算失败，事务回滚，原账目保持不变。

### 12.3 周期切换

1. 应用启动时比较当前日期与活跃周期的预计发薪日。
2. 未到预计发薪日时继续当前周期；到达或超过时显示发薪确认，不自动创建周期。
3. 用户确认工资到账日、本期预算和新的预计发薪日。
4. 在一个数据库事务中归档旧周期、迁移新开始日上的已有账目并创建新周期。
5. 预算不继承上期盈余或超支；快捷项目继续沿用当前配置。
6. 用户选择工资尚未到账时，先修改预计发薪日，再重新计算延长后的当前周期。

## 13. 备份与恢复

### 13.1 导出

- 导出一个带格式版本号的完整 JSON 备份文件。
- 文件包含周期、项目、预设金额、账目和设置。
- 文件名包含导出日期和时间。
- 周期归档后提示用户导出到 iCloud Drive。
- 第一版备份文件不加密，导出时明确提醒其包含个人消费数据。

### 13.2 恢复

1. 读取文件但不立即写入。
2. 校验格式版本、必填字段、金额、日期和引用关系。
3. 展示备份时间、周期数、账目数和项目数。
4. 用户确认后，先生成恢复前安全备份。
5. 在单一数据库事务中用备份替换本地数据。
6. 事务失败则回滚，保留恢复前数据。
7. 恢复完成后重新计算所有周期并校验总额。

第一版不提供合并恢复，以避免重复账目和冲突。

## 14. 错误处理

- 金额无效：阻止保存并定位到金额输入。
- 日期不属于已知周期：阻止保存，并引导用户确认工资到账或调整预计发薪日；不得静默自动创建周期。
- 预计发薪日不晚于开始日：阻止创建或修改并定位到日期输入。
- 已到预计发薪日但未确认：显示等待发薪确认页，不给出未经用户确认的新周期预算。
- 本地存储失败：不更新界面预算，提示重试并建议导出备份。
- 预算计算异常：保留原交易状态，显示可恢复错误，不写入派生结果。
- 备份格式错误：只读校验失败，不改动本地数据。
- 数据库升级失败：停止进入主界面，提供重试和导出原始数据入口。
- Service Worker 更新：不在用户记账过程中强制刷新；新版本在下次安全启动时启用。

## 15. 隐私与安全

- 应用不上传账目、预算、项目或统计数据。
- 静态托管方只能提供程序文件，无法读取 IndexedDB 中的账目。
- 任何获得应用网址的人只会得到自己的空白本地账本。
- 数据安全依赖 iPhone 本身的访问控制。
- 清除网站数据、删除网页 App、设备损坏或系统存储压力均可能造成数据丢失，因此备份不可省略。
- 更换托管域名会形成新的浏览器数据域，旧数据不会自动出现；正式发布后应保持稳定网址。

## 16. 视觉与响应式设计

- 使用已确认的蓝白浅色金融工具风格。
- 深海军蓝文字、皇家蓝主要操作、珊瑚红超支、柔和绿色盈余。
- 适配 iPhone 16 Pro Max 安全区域、圆角屏幕和底部手势条。
- 主要点击目标不小于 44 × 44 CSS 像素。
- 金额是第一视觉层级，装饰从简。
- 支持系统字体放大到合理范围而不遮挡核心金额和按钮。
- 第一版只提供浅色主题，深色模式留待后续版本。

## 17. 部署与手机安装

### 17.1 部署

- 生成静态构建产物并部署到固定 HTTPS 地址。
- 不需要购买 VPS，不部署后端或数据库。
- 正式网址确定后保持不变，避免本地数据因来源地址变化而不可见。

### 17.2 iPhone 安装

1. 使用 Safari 打开正式地址。
2. 点击分享。
3. 选择“添加到主屏幕”。
4. 开启“作为网页 App 打开”。
5. 点击“添加”。
6. 之后从主屏幕图标启动。

第一次加载和程序更新需要联网；应用外壳缓存完成后，记账、查询和统计可离线使用。

## 18. 测试策略

### 18.1 预算引擎单元测试

- 1500 元在 28、29、30、31 天及更长的有效周期中分配后总额严格相等。
- 不能整除的预算按分正确分配。
- 最后一周不足 7 天时只按实际天数获得预算。
- 单日结余完整转入次日。
- 周末结余正确加入下一周并均分。
- 当日超支后全部未来日期正确重规划。
- 总预算耗尽后未来可用为 0。
- 固定支出不影响预算。
- 修改、删除和补记历史账目后结果确定且可重复。
- 最后一周结余成为周期盈余。

### 18.2 数据测试

- IndexedDB 增删改查。
- 数据库版本迁移保留旧数据。
- 事务失败回滚。
- 导出后清空测试数据，再导入能够逐条恢复。
- 非法、缺字段、错误版本备份不会改动本地数据。

### 18.3 界面与端到端测试

- 一键记账、5 秒撤销和普通记账。
- 历史日期补记、编辑和删除。
- 到期只提示而不自动创建周期。
- 工资提前、按期和延期到账时的归档、调整与新周期创建。
- 日历 7 列可变行数排列和状态展示。
- 离线启动、离线记账、恢复联网。
- PWA 安装提示和全屏模式。
- iPhone 16 Pro Max 视口与安全区域。

## 19. 第一版验收标准

1. 用户能在 iPhone 主屏幕以独立网页 App 形式启动。
2. 无网络时能够启动、记账、修改、查询和统计。
3. 高频支出一次点击完成，且 5 秒内可撤销。
4. 任意预算金额在整个周期中分配后无分值误差。
5. 日结余、周结余、超支重规划和历史账目重算符合本规格。
6. 固定支出可记录和统计，但不改变预算可用额。
7. 新周期只能由用户确认工资到账后创建；旧周期独立归档，下一周期不继承盈余或超支。
8. 完整备份可以导出到 iCloud Drive，并在清空数据后完整恢复。
9. 正常程序更新和数据库迁移不丢失账目。
10. 首页、记账、统计和快捷项目页面符合已确认的视觉方向。
